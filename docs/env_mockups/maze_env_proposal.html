Proposal: maze navigation env

How to read the pictures: top-down view. Dark lines = walls. Yellow ball with colored spikes = the robot. Green dot = goal. Blue dashed line = one possible route. The floor color shows the geodesic distance to the goal (green = close, red = far, measured through the maze, not in a straight line).

Three difficulty levels (same env, config choice)

Long corridor. ~40 cells to travel. No wrong turns, but many actions needed. Good first RL target.

Rooms with doorways. The agent must find doors, not just push toward the goal.

Random maze (new layout every episode, ~15 cells). Junctions and dead ends. Straight-line reward fails here — the geodesic reward is needed.

The observation: 16 lidar rays (orange) give wall distances around the ball, plus goal direction and geodesic distance. This replaces the "3 nearest pillars" trick — it works with any wall shape.

Two camera modes

Config picks the mode: camera.view: chase (follows the ball, as now) or camera.view: bird_fixed (one fixed camera above the maze center; the whole episode is visible in one shot).

What I would build (if you say yes)

  • New scenario kind maze: grid maze (cell ≈ 1.5 m, corridors wide enough for the ball), walls as heavy box objects, random layout each episode, with the 3 difficulty levels above as config presets.
  • Geodesic reward: a distance field computed on the maze grid at generation time (like ant_swarm's geodesic field). Progress = geodesic distance decrease. Success bonus stays.
  • Lidar observation for the steering policy: 16 ray distances + goal direction + geodesic distance. Same action space as now.
  • Fixed bird camera as a second camera mode.
  • Heuristic baseline stays as the control: it will fail in the maze, RL has to win.

Path lengths: level 1 ≈ 12–18 m, level 3 ≈ 20–35 m — hundreds of low-level steps, dozens of real decisions per episode.
